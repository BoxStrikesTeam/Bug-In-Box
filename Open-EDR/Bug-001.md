## 📌 Executive Summary

Open EDR (Xcitium / Comodo) bundles third-party libraries directly into its repository. These libraries have **not been updated for approximately 7–8 years**. I identified **12 directly identifiable CVEs** within these dependencies, representing **over 100 known vulnerabilities** in total.

Despite reporting this to the vendor on **June 21, 2026**, and sending **4 follow-up emails**, I received only **one single-sentence reply** ("We will update"). All subsequent requests for a timeline, CVE assignment, or technical clarification were **ignored**.

This repository serves as the official public record of these findings.

## 🔍 What Is the Security Impact?

Open EDR is an Endpoint Detection and Response (EDR) solution. It typically runs with **SYSTEM-level privileges** on endpoints. By leveraging these outdated libraries, an attacker could potentially:

- **Execute arbitrary code** remotely or locally (RCE).
- **Steal sensitive telemetry data** and system information.
- **Crash the EDR agent** (DoS), disabling endpoint protection.
- **Bypass TLS/certificate validation** to intercept communications.
- **Pivot** to other systems in the network.

Since the libraries are **statically linked**, they cannot be patched by system-level updates — they are baked directly into the agent.

## ❓ Why Am I Disclosing This Publicly?

1. **The vendor is unresponsive.** I gave them 30 days and multiple chances to respond.
2. **No security policy exists.** There is no clear channel or process for reporting vulnerabilities.
3. **Users deserve to know.** This is an EDR — security software. If it contains known CVEs, users must be made aware so they can take action.
4. **Supply chain risks are real.** This is a textbook example of how attackers bypass strong security by attacking weak dependencies.

## 🛠️ Recommendations

### For Xcitium / Comodo:
- **Immediately** update all third-party libraries to their latest stable versions.
- Publish a **formal security disclosure policy**.
- Clearly state the **maintenance status** of Open EDR on the repository.
- Respond to security researchers **promptly and professionally**.

### For Open EDR Users:
- **Review your deployment.** If you are using Open EDR, be aware of these risks.
- Monitor the repository for updates (if any).
- Restrict network exposure of the EDR agent.
- Consider alternative EDR solutions if the vendor remains unresponsive.
